# Gateway parity matrix

The Go port is accepted one observable assertion at a time. The baseline is Eigenwise toolshed commit `a8501f251755`, plugin `model-gateway` v0.56.3. A source citation is a registration (not an assertion line): the path is relative to `plugins/model-gateway/`, and ` > ` separates parent and child names. The scope ledger is cumulative at the final gate. This checklist specifies what to test; it does not assert that the port passed. The [reference census](../../test/conformance/baseline/census.tsv) records which source cases passed, failed or skipped. A failed baseline case is an outstanding discrepancy, never a passing result. The operator-guidance checks apply to the **shipped model-gateway skill**: the [plan](model-gateway-go-port.md) preserves its user-facing contract in §1.2 and requires both skills to ship in §4, phase 5. The corresponding toolshed website guide read by the Node test is not a Go distribution requirement. The companion lock is the review-controlled set of row ids; changing it after approval requires the lead’s recorded approval.

Each table line is one assertion. In a source-tests cell, `<br>` separates citations. A named difference is evaluated against its replacement test in [the plan’s difference table](model-gateway-go-port.md#310-differences-from-the-source), not against the superseded Node result. `no-source-test` means the cited requirement has no test directly proving that condition. Independent assertion-site mappings, test classifications and their exceptions are separate from this row lock. In the last column, `integration-from=phase-N@internal/package` records a cited case whose result is reused at a later integration gate; `narrower-from=phase-N@internal/package` records a cited case assigned elsewhere whose narrower predicate belongs to this row’s package. Each distinct mismatching case gate/package is listed. `due-at=phase-gate` means the row is due at the end of its stated phase, not at the owning package task; it is required for every source case classified with `gate=phase` and for checks against the packaged artifacts. An unmarked row is due at its owning task. For packaging, `shipped-source` is the artifact path relative to the pinned plugin and `assertion-site` is the assertion in the source case that checks that artifact. The `no-source-test` manifest-description row carries a supersession-only relation: `supersedes` names the old assertion, `superseded-case` identifies its registration, and `integration-from` locates that case’s gate. None is proof of the new description; count only the Source tests cell for proof or case coverage. CLI command packages are `internal/cli/<command>` as in plan §9. `mixed-with=slug` identifies a changed part of a mixed case; the row covers only the retained predicate. `pending=internal/package.TestName` is a required future test, not passing evidence.

## Reading the catalogue at the pin

- The plan-tool override is implemented but no pinned test sets it. The fast-path case observes the absence of the recovery-module load, not lock acquisition. These requirements have separate rows rather than borrowed citations.
- Windows-only runtime behavior, including the 8 s default probe budget, is outside the first milestone. The 2 s POSIX budget is in scope. The installed-CLI egress experiment and its positive control are not a guarantee about arbitrary CLI versions; the ordinary controlled probe is a separate case.
- “SessionStart always exits 0” describes the notice publisher, not every invocation of the readiness gate. A user-configured host execution failure is not simulated: the source checks the absence of `onFailure`. For deadline exhaustion, use the event-specific Go replacement.
- `hooks/ensure.js` delegates through the registry at the pin but is dormant. The active stable launcher is covered by `test/proxy-upgrade.test.js:116`; the Go contract is the stable binary, not registry traversal or reactivation of the dormant hook.
- The source checks Codex and Grok continuation refusal (not every provider separately); Anthropic passthrough and Codex token counting have their own checks. Sentry-off suppresses genuine-413 rewriting, not the independent legacy-400 normalization.
- For the five adjacent documentation matches in `test/gateway-readiness.test.js:221-225`, each independently required statement has a row even though the enclosing registration is the same.
